# UI16：多通知、八主题与液态玻璃

Windows 版本 1.5.0 NNU UI16，内部构建 2026110203。UI15 / 2026110201 与 UI15.1 / 2026110202 为之前的本地候选；本次发布将以实际验签的线上清单为准。

## 管理与显示

现有版本管理后台支持最多 10 条通知，每条分别设置标题、纯文本正文、主题、前置图标、切换动效及是否发布。支持添加、移除草稿、上移/下移和整体保存/发布/撤下。保存草稿不改已发布列表；发布只包含已启用且标题和正文完整的通知，保持草稿顺序。已有公告原文与发布时间在数据库迁移中保留。

保留五个预览方向：清爽细栏、安全提示、悬浮胶囊、双层卡片、多主题轮播。新增曜石黑、钛金黑、液态玻璃，共八种主题。黑色主题仅作用于公告，不强制改变客户端整体主题。液态玻璃在小范围 ClipRRect 内使用 BackdropFilter，配合渐变细边、内层高光与半透明底色；系统高对比度下使用实色以保证阅读。

所有主题均使用同一个轮播组件，支持 5–60 秒间隔（默认 8 秒）、手动切换与暂停。鼠标停留、键盘聚焦、查看全文、应用不在活动状态或 TickerMode 禁用时不自动切换。通知切换只对透明度、位移或图标变换做有限时动效，不循环闪烁，不滚动跑马灯。减少动态效果设置下停用动画；关闭动效仍正常轮播。

前置图标为客户端内置 Material 图标的白名单，含跟随主题、扩音器、盾牌、铃铛、警示、信息、维护工具、星光、日程、支持、网络或无图标。动效独立选跟随主题、轻柔浮现、图标轻摆、轻呼吸、关闭。后台预览可重播动效，正文全部按纯文本展示，不能注入 HTML、SVG 或脚本。

## 协议与兼容

新客户端请求 `/update-admin/notices.json?protocol=2`，返回 schema=2、announcements 列表和 interval_seconds。限制最多 10 条、响应 128 KiB，验证文字长度、标识唯一性和间隔。未知主题/图标/动效安全降级到默认值。可读取原 schema=1 单公告。

无 query 的旧接口继续返回 schema=1，只提供第一条已发布通知，响应不会携带完整列表导致旧客户端超限。新旧草稿/发布状态均保存在原 admin.sqlite 单行记录的新增列，旧字段继续维护。旧管理页面尝试覆盖多通知列表会返回冲突，要求刷新，防止静默丢失其它草稿。

管理 API 继续沿用现有账号、Passkey、服务器会话、Origin、CSRF 和 revision 冲突校验。发布更新和公告发布是两个独立动作；本次程序上线不会自动发布测试通知或改写管理员的公告正文。

## 验证与回归范围

后端回归覆盖原认证、版本发布、公告草稿隔离，以及多通知排序、过滤、八主题枚举、旧协议兼容、迁移、撤下及过期页面拒绝。CNB 仅构建 update-admin 镜像，在专用 NNU-SecureBuild 本地运行实际镜像验收后按 digest 部署，保持其它容器、账号、Passkey 与原公开公告不变。

Flutter 回归覆盖八主题在窄窗口、深色和 160% 文字下的多条轮播、暂停、全文保持、减少动态效果及既有局域网提醒。另使用同一生产组件的独立 Flutter 壳检查黑色边框与玻璃效果；不启动远控核心，不切断当前网络。四种 Windows 安装文件、本地签名升级包和公开下载按大小、SHA256、Ed25519 与 ZIP CRC 校验。

没有做隔离 Windows 虚拟机的安装、卸载、崩溃恢复及两机实际断网连接端到端验收；原安全审查中的上游遗留告警仍然存在。没有安装、退出或重启用户正在使用的客户端。

既有运行路径的必要变化：`nnu_announcement.dart` 接入版本化列表请求与统一轮播；新模型、样式和轮播逻辑分别放在 nnu_announcement_model.dart、nnu_announcement_style.dart、nnu_announcement_carousel.dart。后台仅改 announcements.py、公告区域 HTML/JS/CSS 和针对性测试；原数据库新增可兼容列。构建助手测试列表加入主题回归。Rust 核心、密码批准、PIN、服务恢复、自动更新安装门槛以及 hbbs/hbbr/API 运行行为不改。

## UI17：自定义标题与磨砂材质

Windows 1.5.0 NNU UI17 / 2026110204 新增磨砂材质，共九种主题。采用高雾度灰白（深色模式为灰蓝）材质、柔和细边和低反光表面，与液态玻璃的高光边框区分。高对比度模式使用不透明底色。

每条公告可独立选择标题字体（主题默认 / 系统黑体 / 宋体 / 等宽）、字号（默认 / 12、13、14、16、18）、字重（默认 / 常规 / 中等 / 加粗），并用取色器自定义标题和图标颜色，或恢复主题默认。只接受六位不透明十六进制颜色，不接受任意 CSS、外部字体或 HTML。字体随本机字体可用情况回退。低对比度色自动调整为可读的黑或白；系统高对比度优先。未设置这些字段的旧公告保持原主题默认。后台保存草稿与发布状态仍独立；schema=1 保持不变，schema=2 增加可选字段，旧客户端忽略新字段并将磨砂主题回退为清爽细栏。

Windows 系统窗口标题、主界面标题栏和 Flutter 应用显示标题改为“RustDesk VIP支持专业版”。仅改变显示文字：common.dart 的 Windows getWindowName 分支、tabbar_widget.dart 的 Windows 标题文本和 main.dart 的 Windows 应用标题必须同步。服务名、程序文件名、协议、安装路径及远控核心不改。原生初始化窗口在 Flutter 接管前仍短暂沿用原生标题。

本次回归范围限公告模型/样式/轮播（字体尺寸与颜色）、后台公告表单/校验，以及上述三处 Windows 显示标题；其余历史修改不纳入本次整理。验证沿用以上范围与未覆盖项。

## UI18：修正实际标题与多平台发行

UI17 遗漏了 DesktopTabPage.emptyTabContent 实际使用的 NnuSupportTitle，导致主窗口可见标题仍是旧名。UI18 / 2026110205 修正此组件的 nnuSupportTitle，并让已定制的 Dart 窗口名称、标签栏和应用标题引用同一常量；Android 首页标题也用同一名称。Windows/Linux 原生启动窗口同步显示新名称，Android 安装包标签与 Linux 桌面快捷方式由打包脚本改为 RustDesk VIP支持专业版。服务/包标识、协议、安装路径与签名身份保持不变。

发布助手必须重新打包：包含新版源码快照、DIY 配方与 Android/Linux 名称处理脚本。新增实际 NnuSupportTitle 文本/提示测试，沿用已有构建前回归入口；这项测试会在旧组件上失败。

本次回归面：nnu_support.dart 的真实标题文本；common.dart、main.dart、tabbar_widget.dart 和 mobile/pages/home_page.dart 的名称引用；flutter/windows/runner/main.cpp 与 flutter/linux/my_application.cc 的启动窗口标题；android_packages.py 的安装标签和 linux_packages.py 的桌面名称。全部是名称显示和分发所必需，不改远控核心、认证、后台公告内容或安装标识。本机覆盖 Windows x64、Android 三架构/通用 APK/AAB、Linux x64；Windows ARM64、Linux ARM64、macOS、iOS 未覆盖。Windows 完整界面不在当前远控会话上重启验收，使用同一真实标题组件的独立壳验收；Android 真实设备远控及逐发行版 Linux 桌面验收仍未覆盖。

构建工具对外名称按用户最终指定统一为“RUSTDESK版本发布助手”（标题栏、页眉、EXE 和桌面快捷方式）。内部配置目录及 AppUserModelID 保持不变，保留已有设置和密钥库。
