# NNU UI15 / UI15.1：局域网直连与客户端公告

Windows 最新候选版本：1.5.0 NNU UI15.1，内部构建 2026110202；上一候选为 UI15 / 2026110201。线上 Windows 正式版仍为 UI14 / 2026110109；Android、Linux 正式版仍为 2026110107。本次候选包未推送，不替换当前运行的 RustDesk。

## 局域网直连

`src/nnu.rs` 的 DEFAULT_SETTINGS 新增 `direct-server=Y`，不是强制覆盖。已明确关闭直连的设备仍保留原选择；用户可在“设置 → 安全”关闭或修改端口。局域网发现 `enable-lan-discovery` 是另一个选项，本次不改它。

监听端口由 `src/rendezvous_mediator.rs::get_direct_port` 决定：未自定义时为 RENDEZVOUS_PORT + 2，即 21118。当时控制端 `src/client.rs::_start` 使用 RELAY_PORT + 1；这在 NNU 的 22222 中继端口配置下实际得到 22223，与监听端口不一致（已在 UI19 修正）。原 UI15 未改连接解析和协议，设计输入为 `192.168.1.20`，自定义端口输入 `192.168.1.20:32100`。

主界面左侧密码下方新增地址卡片，每 10 秒读取直连配置和本机 IPv4 接口，排除回环和链路本地地址，支持多个网卡、地址复制、服务停止与关闭状态。卡片显示的是配置状态和本机接口地址；不宣称防火墙、端口占用或跨网段可达性已经检查。连接仍经过原有密码、批准流程与加密协商，不绕过认证。

UI15.1 复用已验证的 UI15 原生核心；该核心编译时没有传入 NNU_PORTABLE_PASSWORD，不把共享预设密码编入安装包。已有设备保存的密码保持不变，新设备使用原有一次性密码流程。

## 公告

客户端启动时读取 `https://rd.nnu.cn/update-admin/notices.json`，此后每 5 分钟同步。只接受 HTTPS 固定地址，不跟随跳转；响应限制为 16 KiB，验证 schema、标题与正文长度。公告以 Flutter Text / SelectableText 显示，无 HTML、链接执行或远程资源。为空、格式异常或网络失败时不保留消息条空白；长公告最多显示两行，点击展开可滚动、选择的全文。

公告条位于主连接页支持状态栏上方，沿用当前主题颜色与按钮组件。160% 文字缩放和窄窗口已做布局回归。主界面中仍保留首次使用提示、服务状态与支持链接。UI15.1 将公告摘要中的标题与正文合并为单个普通空格，去除首尾空白并将摘要正文的连续空白折叠；公告全文仍保留原始排版。

后台在既有版本发布页增加“客户端公告”，使用原有账号、Passkey、会话、CSRF、Origin 检查和操作记录。草稿与已发布内容独立；保存草稿不改变已发布内容，发布才替换，撤下保留草稿并使公开接口返回 null。并发页面修改使用 revision 冲突检查。标题上限 80 字，正文上限 2000 字。

服务端仅新增 admin.sqlite 中的单行公告表及 update-admin 路由，无 hbbs/hbbr/API 协议改动。CNB `api_trigger_admin` 仅构建和验证管理镜像；本地专用 NNU-SecureBuild 验收镜像后按 digest 部署。既有账号、Passkey 和其他容器保持不变；未在生产服务器构建镜像。正式后台无测试公告。

## UI15.1 离线提醒及改动范围

当客户端尚未连接服务器（包括连接中和不可用）时，左侧局域网卡片增加“暂未连接服务器 / 同一局域网仍可通过 IP 尝试连接。”提示。它以现有 svcStatus 状态响应变化，不主动探测互联网，也不切断本机网络进行测试。只有直连开启、服务未停止、已检测到本机 IPv4 地址时才显示；联网恢复、直连关闭、服务停止或没有地址时收起。

外网或连接服务器不可达，不代表同一局域网的 IP 直连失效；双方仍须处于可互通的局域网，目标直连监听正常且未被防火墙拦截，仍需原有密码或批准。提示使用“尝试连接”，不宣称已经探测目标可达性。

本次修正只改变 nnu_announcement.dart 的摘要空白、nnu_lan_info.dart 对已有服务器状态的观察，以及 nnu_lan_card.dart 的条件提示。其余修改为两项针对性测试、独立预览样例和交付文档。没有改 Rust 核心、连接算法、认证、公告后台或服务器容器，没有安装或重启用户正在使用的客户端。

## UI19 / 2026110206：修正只输入 IP 的真实连接端口

UI18 及之前的 UI15 文档误认为 RELAY_PORT + 1 与监听默认端口相同；NNU 已把 RELAY_PORT 改为 22222，所以只输入 IP 实际连接 22223，而 direct_server 仍默认监听 RENDEZVOUS_PORT + 2，即 21118。这是控制端默认端口选择错误。已由用户确认，显式指定被控端的 21118 端口可进入密码/授权界面。

修正仅为 src/client.rs::_start 的 IP 分支一处表达式，使用 RENDEZVOUS_PORT + 2，与既有监听逻辑一致。不改变中继端口、服务器配置、IP:自定义端口、ID 连接、加密或密码/批准验证。无需被控端改端口，控制端更新后只输入默认监听设备的 IP 即可。自定义监听端口仍输入 IP:端口。

针对性回归直接调用真实 Client::_start 和既有 Session<FlutterHandler>，在隔离网络与临时配置中启动 21118 监听，并检查裸 IP 的实际 TCP 连接；另检查显式自定义端口。没有加入 mock 接口、测试专用产品逻辑、自动端口扫描或额外回退连接。Windows 原生核心重新编译且不编入共享预设密码，各平台与构建工具同步打包。

本次既有运行路径变化仅为 client.rs 的裸 IP 默认端口；其它变更限该文件的回归测试、发布版本元数据、本文说明与构建工具内置快照/配方。此前改动不作整理。未重启或替换当前正在使用的客户端。
